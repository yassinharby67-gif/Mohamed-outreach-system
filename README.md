# Mohamed Outreach System

نظام محمول لتنظيم مراحل الـOutreach من جمع الـLeads لحد تحليل الشاتات. الـRepository ده وثائق وقوالب وقواعد تشغيل، مش نظام بيشتغل لوحده بمجرد رفعه على GitHub.

## مهم قبل أي تشغيل

- النظام Draft-only. مفيش إرسال أوتوماتيكي.
- البيانات الحقيقية والشاتات والـLeads تتحط محليًا خارج الـRepository.
- ما تحطش في الـRepository أسماء كاملة، أرقام، إيميلات، لينكات حسابات حقيقية، IDs، كلمات مرور أو Tokens.
- لازم كل Agent يوضح إيه اللي شافه فعلًا وإيه اللي غير متحقق.
- ما نبدأش تشغيل حقيقي إلا بعد تحديد الأداة والصلاحيات، batch config، شروط التأهيل، موافقة Mapping الشيت، وتجربة 3 Leads.

## مكونات النظام

1. `01-lead-discovery`: جمع خام بحد أدنى Instagram وWebsite.
2. `02-qualification`: التحقق والتأهيل والتحليل العام.
3. `03-crm-and-drafts`: تجهيز CRM والمسودات فقط بعد الموافقة على Mapping.
4. `04-replies`: تصنيف الردود وصياغة الرد التالي.
5. `05-chat-analysis`: تحليل الشاتات السابقة والـGhosting بدون تحويل الصمت إلى حقيقة.

## طريقة الاستخدام المختصرة

1. اقرأ `docs/runbook.md`.
2. حدد `batch config` من القالب في `context/icp.md`.
3. شغّل Discovery فقط، وأخرج بيانات خام.
4. مرر الـLeads للتحقق والتأهيل، مع Label لكل معلومة.
5. اعرض Mapping أعمدة الـCRM للموافقة قبل أي كتابة.
6. جرّب على 3 Leads فقط.
7. راجع المسودات يدويًا.
8. أرسل يدويًا فقط، ثم سجّل الحالة والتاريخ والمنصة.

## اللي اتعمل واللي ما اتعملش

تم تجهيز ملفات المعرفة والقوالب محليًا. لم يتم جمع Leads، ولم يتم فتح أو تعديل CRM، ولم يتم إنشاء Google Docs، ولم يتم إرسال رسائل، ولم يتم إنشاء GitHub Repository حتى الحصول على تأكيد صريح للحساب والاسم.

## قبل أي Push

نفّذ مراجعة محتوى فعلية، وليس الاعتماد على `.gitignore` فقط:

```bash
grep -RInE '(@|https?://|wa\.me|\.com|\.net|\+?[0-9]{7,}|gmail|outlook|client|prospect)' . --exclude-dir=.git
```

أي نتيجة حقيقية لازم تتشال أو تتحول إلى Placeholder.
